# Stable status layout and explicitly checked triggers

Owner request: stop connection-message churn and text-driven layout movement; Check must be reliable and its answer must remain until another explicit check. Existing product design/branding and native Keepresso stay intact. This is a repair of the agreed manual-preview UX, with no new trigger automation or power operation.

Observed causes: paired dashboard renders changing transport diagnostics at variable height; normal snapshots/tick mark cached assessments stale or reset them when any raw settings bytes change; failed-check feedback can survive a later success. Actual Mac log records an8second bounded-worker expiry. A relay tick currently awaits the trigger worker, blocking lightweight state publishing/polling while that check runs.

Chosen repair: stable text slots and short connection presentation; immutable last completed manual assessment with separate attempt/progress/context metadata; a bounded asynchronous relay read job so routine telemetry continues. Animation alone would keep the underlying movement; extending freshness would misrepresent proof. Neither is used. A larger project/UI redesign is unnecessary. User's existing requirements specify these outcomes; implementation choices below preserve those requirements.

Contract:
- Trigger checks run ONLY for explicit refresh_triggers; no timer, automatic retry, prewarm or permanent engine. Keep last rows, verdicts and checkedAt after status polls, route changes, failed checks and brewing-mode changes. Refresh success (including partial unknown input) replaces it exactly, including an empty rule list. Failed/cancelled checks retain it.
- Optional backward-compatible triggers fields: checking:Bool?, outdated:Bool?, checkError:String?. state continues to describe last assessment quality; progress/error/context do not clear a prior assessment. No agent details.
- Compare canonical ruleSet configuration, not arbitrary raw preference bytes/non-trigger fields. Changed rules/native lifecycle flag outdated without clearing rows/time; ordinary brewing status does not invalidate the historical result.
- Parent worker bound12s includes startup allowance; child engine watchdog remains8s and current sampling stays bounded. Android explicit check timeout25s covers relay/worker/delivery inside existing30s request validity. No freshness/authentication extension (15s proof remains15s).
- RelayCoordinator executes ONLY refresh_triggers as a cancellable read job, one per device, max8. Lightweight sync/state continues while it runs. Deduplicate in-flight IDs/body, reject a competing read without queuing; stop/revoke/epoch rotation cancels and rejects late results. Mutations retain existing execution/journal/no-replay rules.
- Android commits manual trigger data from the matching explicit check response, independently of telemetry capture ordering. Ordinary status can seed an initial historical view and flag context changes, but cannot replace an existing assessment. Keep values during Check; update progress/error separately and clear prior failure after success.
- Paired dashboard uses calm connection text, logs low-level transport diagnostics, and fixed line counts/slots for volatile text. Keep all security/freshness behavior and meaningful unknown/error states. No animateContentSize cure, new agent detail, big blank feedback box or truncated-away uncertain-command meaning. Preserve typography/colors/icons and same-line Active triggers/time/Check.
- No owner credentials reset, Keychain reads by tools, permission grants, native settings/power commands or official/vendor edits. Retain package/signing identity/pairing/cloud setup.
- Verify in dedicated emulators, scoped regression tests and final review. Prepare Mac0.5.2/build14 + Android0.5.2/code5002; no owner delivery until both packages verified and phone connected. No release publishing.
